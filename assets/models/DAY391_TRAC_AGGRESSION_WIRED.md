# Day 391 — TRAC-1 wired, behind the surface Day 347 said it would need

`trac_aggression_v1` is the first text model in the app, and the first
model in the project whose training corpus is permissively licensed.

## 1. Why this one ships and `distress_text_v1` still does not

Day 347 shelved `distress_text_v1` and listed what would change that: a
product decision plus a surface. It is tempting to read today's wiring as
that decision arriving by the back door. It is not, and the difference is
worth being precise about:

|  | `distress_text_v1` | `trac_aggression_v1` |
|---|---|---|
| reads | the **user's own** typed text | a message **someone else sent** them |
| infers | clinical state — Anxiety, Depression, **Suicidal** | whether wording is hostile |
| posture | health inference | closer to a spam filter |

`distress_text_v1` remains in `work/m7_distress_text/`, unshipped, for
exactly the reasons Day 347 gave. Day 353B additionally confirmed its one
*measurable* blocker is real: no independent text corpus exists to
cross-corpus test it — `mental_health_feature_engineered.csv` is 100.0% the
same 48,928 texts as the training source.

This is also **not M7**. M7 needs victim-perspective distress ("someone is
following me"). TRAC is aggressor-perspective. M7 stays blocked.

## 2. The consent posture is the design

* **User-initiated only** — nothing is read in the background. The user
  pastes text and presses a button.
* **On-device** — no network call; the text never leaves the phone.
* **Not retained** — the controller is cleared on dispose; nothing goes to
  storage, logs or analytics.
* **Not an SOS trigger** — it does not escalate, notify contacts, or feed
  the DCS fusion path. It informs the person already reading the message.

This is deliberately **not** in `kZapsafeModels`. That catalogue is the
live-detection roster, and putting a user-initiated advisory tool in it
would imply it runs in the detection pipeline. It does not, and the
registry still declares six slots.

## 3. Which number the UI shows

```
in-corpus (TRAC-1 dev)               0.8312   CI [0.8196, 0.8423]
cross-corpus (Indo-HateSpeech)       0.7081   CI [0.7028, 0.7134]
length-only baseline, in-corpus      0.6177
length-only baseline, cross-corpus   0.5223
```

**The screen quotes 0.71.** The flattering number is the in-corpus one and
it is not what describes the model on text it has never seen. TRAC-1 is the
first model in this project to survive a cross-corpus test at all
(`m3_violence` went 0.9126 → 0.4821; scream v3 0.839 → 0.7675), but
surviving is not transferring intact.

Caveat that measurement cannot settle: Indo-HateSpeech labels *hate
speech*, TRAC labels *aggression*. Related constructs, not identical, so
some of the 0.12 drop is definitional rather than failure.

## 4. Bands, not a binary, and why there is a floor

Cross-corpus calibration is unknown, so a single threshold would claim more
than the model supports. `classify()` returns four states — `hostile`
(≥ 0.60), `unclear`, `notHostile` (< 0.40), and `tooShort`.

**The empty string scores 0.3322.** The model has a non-zero floor, so a
threshold placed carelessly would call silence hostile. Two guards: fewer
than 2 tokens returns `tooShort` with no score at all, and a test asserts
both thresholds sit above the measured empty-input score.

0.60 rather than 0.50 because this is advisory — in-corpus that trades
recall 0.819→0.675 for precision 0.855→0.896, and telling someone a benign
message is a threat is the failure that destroys trust in the feature.

Truncation is surfaced, not hidden: past 60 tokens the model cannot see, and
the UI says so rather than scoring a long message as if it read all of it.

## 5. The tokenizer is where the bug would have been

`[a-z0-9']+|[^\u0000-\u007f]+`, lowercase first. The second branch is
load-bearing — a plain `[a-z0-9']+` **deletes every Devanagari character
silently**, returns an all-pad vector, and the model still answers 0.33
without throwing. That is this project's recurring failure shape.

`test/day391_trac_aggression_test.dart` (22 tests) pins the Dart tokenizer
against a fixture generated by the *same* Python regex and the *same*
`.tflite` that scored 0.7081, covering: Devanagari, romanised Hindi, mixed
script at the ASCII boundary, apostrophes inside tokens, OOV≠pad, empty,
80→60 truncation, emoji (where Dart's UTF-16 and Python's code points could
have disagreed, and do not), and case folding. One test reproduces the
latin-only regex and asserts it returns `[]`, so the file states the bug it
guards.

`flutter test` cannot execute a `.tflite`, so scores are not asserted there
— the gate does that instead.

## 6. Gate

```
trac_aggression_v1.tflite   2723.1KB   ok   n=3000 AUC=0.836 sep=0.3001
```

Routed by input contract — `[1,60] int32` returns before any float path,
because these are token ids and normalising them would be catastrophic
rather than merely wrong. Scored on held-out TRAC dev rows (6,002
available, 3,000 sampled). That 0.836 is the **in-corpus** figure and the
fixture's docstring says so; the cross-corpus 0.7081 is the honest one.

**Licence: Apache-2.0** — the only entry in the gate's provenance table that
is not Non-Commercial, research-only or unstated.

## 7. Cost

2.7 MB of `.tflite` plus 364 KB of vocabulary, on every install. Day 346B
deleted `scream_classifier_v3` for being 2.8 MB with no consumer, and Day
347 refused `distress_text_v1` partly for the same reason. The difference
here is that there is now a consumer. It is still the largest single asset
in the bundle after the gunshot model, and if the Message Safety Check
screen is ever removed, this must go with it.
