# Day 280 — w1 fusion (M1 scream + M2 motion) real evaluation

Follow-up to `DAY278_REMAINING_BLOCKED_RECHECK.md`, which found `w1` was the
one `w_*` fusion head whose two upstream models (`m1_scream_v2`,
`m2_motion_v2`) are both confirmed wired-and-working on real data, and that
`build_w1_dataset()` already points at real data sources — flagged as
"ready for a future retrain/eval session, not attempted." This session did
that eval.

A trained, exported `w1` artifact already exists — it did not need training
from scratch:

  (+ `_f32.tflite`, `_norm.json`, `_report.json`)

  It has never been wired.

## Real evaluation of the existing model

Read `build_w1_dataset()` (`day106_fusion_common.py` lines 388-430) and
`train_fusion_model()` (lines 522-599) directly, and read the recorded
`w_audio_motion_fusion_report.json`:

```
test_auc: 0.9568, n_samples: 6200, production_gate_auc: 0.88, production_pass: true
real_pairs: 2200 (35%), synth_pairs: 4000 (65%)
```

**This AUC does not measure what it appears to measure.** The label `y` for
every sample — both the "real" 2200 pairs (built from real RAVDESS scream
audio scored by `m1_scream_v2` and real MobiAct/PAMAP2/UCI-HAR IMU windows
scored by `m2_motion_v2`) and the 4000 synthetic pairs — is generated by a
**hardcoded threshold rule applied to the same two scores the model
receives as input**:

```python
y.append(1 if s1 > 0.45 and s2 > 0.5 else 0)   # positive pairs
y.append(0 if s1 > 0.35 or s2 > 0.45 else 0)   # negative pairs (always 0 here)
```

and the model's 4 input features are `[s1, s2, s1*s2, |s1-s2|]` — a
deterministic, invertible function of exactly the two variables the label
rule is defined on. There is no independent ground truth anywhere in the
pipeline (no annotation of "this real scream+motion pair was an actual
combined distress event") — the target the network is trained to predict
is a smoothed version of `AND(s1>0.45, s2>0.5)`, a rule that is trivial to
fit with 4 engineered features that already contain the product and the
threshold-relevant magnitudes. A 16-8-1 MLP reproducing a 2-variable AND
gate at AUC 0.9568 is expected regardless of whether M1/M2's scores carry
any real signal at all — it is measuring function-approximation capacity,
not real combined-risk discrimination.

This is the same category of problem this week's triage flagged elsewhere
(labels defined by a transform of the model's own inputs rather than
independent ground truth) — it does not mean the underlying idea (fuse two
already-validated real scores) is wrong, only that the reported 0.9568 AUC
is not evidence the *learned* fusion adds anything beyond the hand-written
`AND(s1>0.45, s2>0.5)` rule it was trained to mimic.

### Direct check: does the model add anything beyond the rule it was trained on?

Loaded the real `.tflite` via `tf.lite.Interpreter`, applied the real
`_norm.json` mean/std normalization, and ran it on a 6x6 grid of `(s1, s2)`
pairs spanning `[0.10, 0.85]` (real M1/M2 operating ranges), comparing the
model's raw output to the literal `AND(s1>0.45, s2>0.5)` rule it was
trained against (36 points, full output logged):

- Every point where the rule says 0 (either score below its threshold): the
  model outputs `<= 0.018`, i.e. correctly and cleanly negative everywhere
  the rule is negative.
- Every point where the rule says 1 (both scores above threshold): the
  model does **not** reproduce the rule's hard `1.0` — it stays low
  (0.001-0.013) near the boundary (e.g. `s1=0.55,s2=0.55` -> 0.001;
  `s1=0.70,s2=0.55` -> 0.003) and only rises toward 1 when *both* scores
  are well past the threshold (e.g. `s1=0.70,s2=0.70` -> 0.560;
  `s1=0.85,s2=0.85` -> 0.913). Mean absolute difference from the hard rule
  across the grid: 0.153.
- Net shape: a smooth, monotonic AND-like gate that is **more conservative**
  than the literal training-label rule near the boundary, converging to it
  only when both inputs are jointly high. This still confirms the core
  finding by direct inference rather than by reading the training code
  alone: the model has no signal beyond "how far both s1 and s2 jointly
  exceed a threshold" — a function of exactly the two scalar inputs the
  labels were also generated from. There is no real, independently
  verifiable event-level test set (e.g. real recordings labeled "this was
  an actual combined scream+fall incident" vs "this was not") anywhere in
  this repo's datasets to score the model against instead — that data does
  not exist locally or in the Drive folder catalogued in
  `DAY278_REMAINING_BLOCKED_RECHECK.md`.

## Conclusion: not wired

Per this week's standing rule (wire only if it clears a genuinely useful,
real-data-verified bar), `w1` does **not** clear that bar: the only number
available (0.9568 AUC) is a measurement artifact of circular labeling, and
there is no real independent dataset to produce a trustworthy substitute
number. Retraining would not fix this — `build_w1_dataset()` would need a
genuinely independent label source (e.g. real annotated combined-incident
recordings), which does not exist in this project's Kaggle account or
Drive folder, the same "genuinely blocked, no new path" conclusion Day 278
reached for `w2`-`w5`, just for a different reason (labeling circularity,
not missing upstream models).

Net effect: `w1` moves from "ready for eval, not attempted" (Day 278) to
"evaluated, real numbers do not support wiring" (Day 280) — not fabricated,
not assumed, checked by direct inference against the real exported
`.tflite`.

**Not wired.** No backend, detector, or pipeline changes made this session.
